## What broke
The test deliberately uses a 50 ms timeout on the first attempt to provoke a failure, then relies on Playwright’s retry mechanism to rerun the test with a 10 s timeout. In the current CI configuration `testInfo.retry` is always 0 because retries are disabled, so the second attempt never runs and the locator times out. The failure is not due to a missing element or selector drift.

## Suggested fix
Enable retries for this test (or globally) and keep the existing logic, e.g.:

```ts
// In playwright.config.ts
export default defineConfig({
  retries: 1, // enable one retry
  // …
});
```

or, if you prefer to keep the test without relying on retries, remove the race simulation:

```ts
// tests/demo/ui-demo.spec.ts
// const timeout = testInfo.retry === 0 ? 50 : 10_000;
await expect(loginPage.alert).toHaveText(
  'Incorrect email address or password',
  { timeout: 10_000 }
);
```
