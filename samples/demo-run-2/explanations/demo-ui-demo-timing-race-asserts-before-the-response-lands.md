## What broke
The test intentionally uses a 50 ms timeout on the first attempt, but the alert element is rendered after the network round‑trip, which exceeds this window. Playwright treats the timeout as a failure, and the test never reaches the retry where the longer timeout would succeed. The test logic assumes a failure on first run, but the framework aborts the test on that failure.

## Suggested fix
Replace the race‑condition assertion with a proper wait, e.g.:

```ts
// Remove artificial short timeout
await expect(loginPage.alert).toHaveText(
  'Incorrect email address or password',
  { timeout: 10_000 }
);
```

If you still want to verify the race, wrap the first expect in a try/catch and ignore the timeout error, then let the retry handle the real check.
